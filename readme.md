# Языки для Rotor

Официальный репозиторий языковых пакетов для движка [Rotor](https://github.com/visavi/rotor).

Каждый подкаталог — языковой модуль: он добавляет в движок новый язык через механизм `publish`, не трогая ядро. При пуше workflow `Update Registry` собирает релиз каждого модуля и пересобирает `registry.json`.

## Установка

Добавьте этот реестр в AdminPanel → Модули → Реестры:

```
https://github.com/visavi/rotor-languages/releases/download/registry/registry.json
```

После этого языки появятся в каталоге (AdminPanel → Модули → Каталог) и установятся в один клик. Язык сам попадёт в переключатель — `getAvailableLanguages()` сканирует `resources/lang/*`.

## Как устроен языковой модуль

Минимум — `module.php` с метаданными и картой `publish`:

```php
<?php

return [
    'name'        => 'Deutsche Sprache (Немецкий язык)',
    'description' => 'Немецкий перевод интерфейса',
    'version'     => '1.0.0',
    'requires'    => '14.0.3',
    'author'      => 'Vantuz',
    'email'       => 'admin@visavi.net',
    'homepage'    => 'https://visavi.net',

    'publish' => [
        'stubs/lang/de'      => 'resources/lang/de',
        'stubs/flags/de.svg' => 'public/assets/flags/de.svg',
    ],
];
```

| Источник (в модуле) | Назначение (в движке) |
|---|---|
| `stubs/lang/<код>` | `resources/lang/<код>` — серверные (`main.php`) и JS (`main.json`) переводы |
| `stubs/flags/<код>.svg` | `public/assets/flags/<код>.svg` — флаг для переключателя языка |

Первый ключ `main.php` — `'lang' => '...'` — родное название языка для переключателя. JS-переводы (`main.json`) отдаёт `@translation`.

## Перевод чужих модулей

Языковой пакет может доперевести и другие модули — достаточно добавить запись в `publish` с назначением внутрь чужого модуля:

```php
'stubs/forum/lang/ol' => 'modules/Forum/resources/lang/ol',
```

Публикация в чужой модуль выполняется **только если он есть на диске**: ядро (`Module::getPublishMap()`) пропускает запись, чей путь назначения ведёт в отсутствующий `modules/<X>`.

Порядок установки не важен: установка/включение любого модуля запускает полную синхронизацию (`Module::syncAll()`), которая заново публикует все активные модули. Поставят Форум позже языка — перевод подмешается сам. Те же гарантии у `module:sync` и обновления ядра.

> Условная публикация требует поддержки в ядре (проверка в `Module::getPublishMap()`). На старом ядре без неё запись скопируется безусловно и создаст пустой `modules/Forum`, если Форума нет.

## Фолбэк

Набор ключей лучше держать полным (на базе `resources/lang/ru`). Недостающие ключи автоматически падают в фолбэк `ru` (`config/app.php` → `fallback_locale`) — новый ключ в ядре не сломает перевод.

## Жизненный цикл

- **Установка/включение** — файлы копируются (`publish`).
- **Отключение/удаление** — файлы удаляются (`unpublish`).
- **Обновление ядра** — файлы перепубликуются автоматически (`module:sync`).

## Именование

Папка модуля = его id: под этим именем он ставится в общий `modules/` и попадает в список модулей админки вперемешку с функциональными модулями из других реестров. Чтобы языки не пересекались по id (`Game`-язык vs `Game`-модуль) и группировались в списке, называйте их по схеме `Lang<Язык>`:

```
LangOlbanian, LangGerman, LangEnglish…
```

## Добавление языка

1. Создайте папку `Lang<Язык>/` с `module.php` (name, description, version, requires, author) и картой `publish`.
2. На обновлениях поднимайте `version` и дописывайте секцию `## X.Y.Z` в `changelog.md`.
3. Запушьте в `master` — workflow соберёт релиз и обновит реестр.
