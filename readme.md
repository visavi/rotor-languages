# Языки для Rotor

Официальный репозиторий языковых пакетов для движка [Rotor](https://github.com/visavi/rotor).

Каждый подкаталог — языковой модуль: он добавляет в движок новый язык, не трогая ядро. При пуше workflow `Update Registry` собирает релиз каждого модуля и пересобирает `registry.json`.

## Установка

Добавьте этот реестр в AdminPanel → Модули → Реестры:

```
https://github.com/visavi/rotor-languages/releases/download/registry/registry.json
```

После этого языки появятся в каталоге (AdminPanel → Модули → Каталог) и установятся в один клик. Язык сам попадёт в переключатель — `Locale::available()` сканирует `resources/lang/*` и `resources/lang/*` включённых модулей-языков.

## Как устроен языковой модуль

Минимум — `module.php` с метаданными, каталог `resources/lang/<код>` и флаг:

```php
<?php

return [
    'name'        => 'Deutsche Sprache (Немецкий язык)',
    'description' => 'Немецкий перевод интерфейса',
    'version'     => '1.0.0',
    'requires'    => '14.7.0',
    'author'      => 'Vantuz',
    'email'       => 'admin@visavi.net',
    'homepage'    => 'https://visavi.net',

    'publish' => [
        'stubs/flags/de.svg' => 'public/assets/flags/de.svg',
    ],
];
```

| Путь в модуле | Что это |
|---|---|
| `resources/lang/<код>` | серверные (`main.php`) и JS (`main.json`) переводы |
| `resources/lang/vendor/<модуль>/<код>` | перевод чужого модуля |
| `stubs/flags/<код>.svg` | флаг для переключателя, копируется в `public/assets/flags/<код>.svg` |

Переводы не копируются: ядро подключает `resources/lang` модуля-языка как ещё один путь переводов (`Locale::addPath()`), и его файлы дополняют переводы ядра, а не уходят в namespace модуля, как у обычных модулей. Модуль-язык ядро узнаёт по имени `Lang<Язык>` (см. «Именование»). Ни ядро, ни чужие модули не получают файлов, которые висели бы в их git. Флаг — единственный публикуемый файл, в git ядра он проигнорирован.

Первый ключ `main.php` — `'lang' => '...'` — родное название языка для переключателя. JS-переводы (`main.json`) отдаёт `@translation`.

## Перевод чужих модулей

Перевод модуля кладётся в `resources/lang/vendor/<namespace>/<код>/`, где `<namespace>` — имя модуля в snake_case:

```
resources/lang/vendor/forum/ol/forums.php   →   __('forum::forums.*') для локали ol
```

Так Laravel подмешивает переопределения пакетов. Модуля нет — файл просто не читается, порядок установки не важен.

Правки админа в `resources/custom/lang` подключаются после модулей-языков и побеждают их.

## Фолбэк

Набор ключей лучше держать полным (на базе `resources/lang/ru`). Недостающие ключи автоматически падают в фолбэк `ru` (`config/app.php` → `fallback_locale`) — новый ключ в ядре не сломает перевод.

## Жизненный цикл

- **Установка/включение** — `resources/lang` подключается, флаг копируется (`publish`).
- **Отключение/удаление** — язык пропадает из переключателя, флаг удаляется (`unpublish`).
- **Обновление модуля** — переводы обновляются сразу, перепубликация не нужна.

## Именование

Папка модуля = его id: под этим именем он ставится в общий `modules/` и попадает в список модулей админки вперемешку с функциональными модулями из других реестров. Чтобы языки не пересекались по id (`Game`-язык vs `Game`-модуль) и группировались в списке, называйте их по схеме `Lang<Язык>`. Это не только соглашение: по префиксу `Lang` + заглавная буква ядро (`Module::isLanguage()`) понимает, что модуль — язык. Префикс зарезервирован, функциональный модуль так называть нельзя:

```
LangOlbanian, LangGerman, LangEnglish…
```

## Добавление языка

1. Создайте папку `Lang<Язык>/` с `module.php` (name, description, version, requires, author), каталогом `resources/lang/<код>` и флагом в `publish`.
2. На обновлениях поднимайте `version` и дописывайте секцию `## X.Y.Z` в `changelog.md`.
3. Запушьте в `master` — workflow соберёт релиз и обновит реестр.
